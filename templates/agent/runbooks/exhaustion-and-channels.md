# Runbook：穷尽检查与渠道探索

> 从 AGENTS.md 下沉（2026-09-16）。**在准备说「拿不到 / 无法完成 / 数据不可得」之前读这个文件。**
> 触发条件：任何时候你准备对用户说「拿不到 / 未取得 / 无法完成 / 数据不可得」，先过这一关。

---

## 1. Exhaustion Check — 禁止只列「现成源」

只试过现成公开 API 就下结论 = 没穷尽。写「拿不到」之前，必须**书面列出至少一条「自己构建数据」的路径**，并说明为什么不走。

**反例（2026-09-13 真实失败）**：
```
❌ 「Libraries.io 要登录、ecosyste.ms 要付费、deps.dev 只给单包 —— 全站 Top10 未取得」
```
它试的全是「去找现成的」，没有一条是「自己造」。**正确写法**：
```
✅ 「现成源均不可得。自建路径：PyPI 官方 Simple Index（https://pypi.org/simple/，
    公开无限制）抓全量包名 → 批量拉各包 requires_dist 元数据 → 本地建反向索引 → 排序。
    不走的原因：（必须写真实原因，如数据量/时间预算），而不是「麻烦」。」
```

### 「没有现成 API」= 触发自建管线，不是任务失败

许可范围内的公开数据，默认认为**可自行采集、可自行计算**。
把「找不到现成接口」当成「任务不可完成」，是最严重的偷懒。
优先考虑：官方全量索引 / 公开数据集（如 BigQuery public datasets）/ 直接抓元数据自建索引。

### 必须先交「部分交付」，不许交空表

在等全量数据的同时，**先交付一份口径明确的近似结果**，再补全量。
```
❌ 交一张全空的 Top10 表 + 一页「未取得」说明
✅ 交「抽样口径 Top10」：如抓 N 个热门包的依赖关系，排出该范围内的 Top10，
   明确标注「本榜为抽样口径（覆盖 N 包），全站口径待补」。
```
**一张标了口径的近似榜，价值远大于一张空表。** 空表等于没干活。

### 只有这四种情况才允许停下问人

凭据/授权缺失 · 不可逆破坏或数据丢失 · 需要外发信息 · **上述自建路径全部真实失败（并给出失败证据）**。
除这四种，一律继续推进，换方案直到出活。

## 2. Channel Exploration Protocol — 失败先分类，再决定动作

**背景**：17:40 行情任务，三个数据源连续 TLS 失败即报「无法获取」。实际根因是出口节点传输层故障——换任何数据源都无效，换传输立刻全通。**三个源全挂 ≠ 没有渠道，可能只是同一条管道挂了。**

每次失败归类为**四种**，动作完全不同：

| 失败类型 | 判定 | 正确动作 |
|---|---|---|
| **源没这类数据 / 口径不对** | 数据问题 | 换源 |
| **HTTP 429 / 503 + Retry-After** | **限流，不是故障** | 退避重试 ≥3 次（2s→5s→10s）→ 换 UA/请求头 → 换等价端点或镜像（OpenAlex ↔ Crossref ↔ PubMed ↔ arXiv ↔ PMC）→ 换出口 |
| **TLS 握手失败 / 超时 / dial error / 连接重置 / 403** | **传输层故障** | 换出口节点 → 换协议栈（curl ↔ python urllib ↔ node fetch）→ 浏览器（能执行 JS 过反爬挑战）→ 明文/CSV 端点。**此时换源是安慰剂** |
| **HTTP 200 但内容是挑战页 / 验证码 / JS 渲染空壳** | 反爬 | **浏览器能过 JS 挑战，curl 不能**；curl 失败 ≠ 网站不可用 |

### 真实事故（2026-09-15）—— 一次 429 就宣布渠道不可用

学术检索任务里 OpenAlex 返回 429，agent 据此判定「Crossref / Semantic Scholar 也不可用」，最终交付 **0 篇文献**。复测发现 **Crossref 在同一沙箱内 6/6 次全部 200 可用**、**PubMed 从未被尝试且实测返回 18 条真实文献**。

**禁止**：一次 429 就宣布「该渠道不可用」，或把「我没充分重试」写成「渠道不可用」。

### 判定「某渠道不可用」的唯一门槛

该渠道已完成 **≥3 次退避重试 + 换过 UA/端点**，且报告里贴出每次的 HTTP 状态码。达不到这个门槛，就只许写「本次未取到」，不许写「不可用」。

### 「找不到渠道」的最低门槛

说「没有任何可用渠道」之前，必须在报告里先交**探索清单**：**≥8 个候选**（不同源 × 不同端点形态 JSON/CSV/页面 × 浏览器路径 × 用搜索引擎现查的线索），每个标注失败分类（传输/反爬/无数据）。

清单里只要有一个「传输」类且换层动作没做，就不许报。

### 与 Hard tool budget 的边界

Hard tool budget（防交互轮刷屏）**不适用于任务型数据获取**。任务型取数遇到失败时：写 checkpoint → 按上表分类 → 换层/换源继续 → 交付时汇报每层结果。
「budget 用完」不是提前交「无法获取」的理由；要省的是刷屏，不是探索。

### 交叉验证与部分交付

拿到数据后：**两个独立源交叉一致才可信**。部分数据先交，缺的标注原因继续补。
