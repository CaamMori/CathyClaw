# Runbook：数据与交付验收（防幻觉 / 口径 / 回验）

> 从 AGENTS.md 下沉（2026-09-16）。**涉及数据处理、数值计算、外部抓取时读这个文件。**
> 触发门槛：交付物含**计算得出的数字**、**批量数据处理**、**外部数据抓取**三者之一 → 本文件全部规则强制生效。

## 1. 禁止幻觉 —— 九条铁律

**本部署真实事故**：交付 PDF 时声称「已使用系统 Noto CJK 字体生成」，用 `pdffonts` 一查——只有 `DejaVuSans`(Type 3)、**无任何中文字体、无文本层**。这比直接失败更严重，因为用户会照着假结论做决策。

1. **没执行过的命令，不许说执行过**。每一句「我已验证/已检查/已生成」背后都必须有一次真实工具调用，且输出能贴出来。
2. **不许用源文本冒充验证结果**。你写进去的文本 ≠ 从产物里抽出来的文本。要证明 PDF 有中文，就跑 `pdftotext` 贴输出；要证明图里有中文，就跑像素密度/字体检查贴数值。
3. **结论必须带证据**。`pdffonts` 输出、`pytest` 的 `N passed`、HTTP 状态码、文件字节数——这些才算证据；「应该没问题」「已确认」「按预期生成」不算。
4. **不确定就标未验证**。宁可说「未验证，卡在 X」，也不许说「已完成」。
5. **失败要说人话**：现象 → 根因 → 已尝试 A/B/C → 建议下一步。**禁止**只说「做不到」就结束。
6. **数字不许编**。抓不到的数据写「未获取」，不许用臆测值填充，也不许把泛化数字伪装成针对具体日期/人数/场景的报价。
7. **Mock 测试通过 ≠ 功能可用**。本部署 `httping` 曾做到 **10 passed / 覆盖率 97%**，但真实 HTTPS 站点的 `tls_days_remaining` **恒为 null** —— 因为测试用 `Mock()` 伪造了 `response.raw._connection.sock.getpeercert()`，绕过了 urllib3 的真实对象生命周期（`response.content` 读完后 `_connection` 被释放为 `None`，真实代码必然抛 `AttributeError`）。
   **覆盖率是误导性指标：它只证明代码被执行过，不证明真实环境下走的是成功分支。** 凡涉及外部资源（网络 / 文件系统 / 数据库 / 浏览器 / 子进程 / 证书）的功能，除 mock 单测外，**必须至少对真实目标跑一次并贴出真实输出**。
8. **不许静默吞异常**。`except ...: return None` 是一种**伪装成正常的失败**——调用方看不出区别。真要返回默认值，必须在返回值里标记原因（例如 `error` 字段写清楚），或在日志/输出中显式说明「该字段未获取，原因：X」。**没有 `error` 字段的 `None` 等同于骗人**。
9. **说「工具/环境不可用」之前，必须贴出最近一次工具调用的完整返回**。本部署用户9 第三轮复测时，Agent 写完了正确脚本、却在执行前声称「工具不可用」并停手结束——**而同一条命令手动跑，正常返回、断言器退出码 0**。根因不是工具坏了，是长脚本生成耗尽了单轮额度，模型把「我不会继续」伪装成了「我不能继续」。
   这与「一次 429 就报渠道不可用」本质相同：**把内部限制外化成外部不可用**。因此定死四条：

| 编号 | 规则 |
|---|---|
| **9a** | **无返回即托词**。任何「工具不可用 / 环境不支持 / 命令跑不了 / 没有权限」的结论，**必须在同一条回复里贴出最近一次相关工具调用的完整原始返回**（命令、退出码、stdout/stderr 原文，不许转述、不许摘要）。**贴不出原始返回的「不可用」，一律视为模型托词，不作数。** |
| **9b** | **单次失败 ≠ 不可用**。一次调用失败/超时/空输出，只能得出「这一次失败了」。必须先**原样重试 1 次**，再考虑换参、换路径、换替代工具，然后才允许下结论。禁止「一次不成就宣布不可用」。 |
| **9c** | **停手必须交代**。确需停下（额度/轮次/长度限制）时，必须明说「我因为 <具体原因> 在本轮无法继续」，并给出已完成的部分与下一步要跑的确切命令——**禁止用「工具不可用」这类外部归因掩盖「我停下来了」**。 |
| **9d** | **被安全规则/preflight 拦截 ≠ 工具不可用**。属于「换写法就能过」，详见 `runbooks/exec-safety.md` §3。 |

## 2. 清洗口径断言器 —— 交付前必跑

**R20 事故二次复发记录**：首次修补只写了文字规则「符号按业务语义决定」，复测中**同一缺陷再次复发**，且形态更隐蔽：

| 轮次 | 7月成本 | 7月利润 | 偏离正确值 | 形态 |
|---|---|---|---|---|
| 正确解 | 44811 | 12923 | — | 按『类型』字段 + 绝对值 |
| 第一轮 | 43117 | 14617 | −1694 | 字符串符号丢失后被 `<0` 条件排除（**静默漏算**） |
| 复测 | **41423** | **16311** | −3388 | 收入用『类型』口径、成本用『符号』口径（**两套标准混用**） |

复测的关键证据链：7 月成本行 71 笔，**绝对值和 = 44811（正确）**，**带符号和 = −41423（复测所报）**；
且 `57734 − 16311 = 41423` —— 说明成本栏不是算出来的，是**用「正确收入 − 错误口径利润」倒挤出来**的。
同一份脚本里收入走一套判据、成本走另一套，**没有任何步骤检查过两者是否自洽**。

**结论：文字提醒不足以约束此类缺陷。必须运行断言器。**

### 强制流程

凡处理**含数字的表格数据**（xlsx/csv），交付前**必须**执行：

```bash
# 1. 先按'类型字段 + 绝对值'这一唯一口径生成结果 json（monthly + cleaned_rows 两个字段）
# 2. 跑断言器，退出码非 0 则禁止交付、回修后重跑
python3 /opt/tools/verify_ledger.py <原始文件> <你的结果.json>
#    退出码 0 = 通过；1 = 不通过
```

断言器检查三件事（任何一项失败即禁止交付）：
1. **口径一致性**：逐月比对「你的成本」与「权威口径成本」（按『类型』字段、金额一律取绝对值）
2. **双向勾稽**：`收入 − 成本 − 利润` 必须恒等于 0，残差 > 0.5 即失败
3. **异常清单完整性**：所有文本型/空值金额必须逐条列出，条数对不上即失败

### 铁律（三条，违反任一条即为 P0）

1. **一个数据源只能有一套口径**。收入与成本必须使用**同一个判据**。选了「按类型字段」就全程按类型字段；不许收入按类型、成本按符号。
2. **禁止用减法倒挤任何汇总数字**。`成本 = 收入 − 利润` 这种写法意味着你放弃了独立核算，两个错误会互相掩盖。每个汇总值都必须由明细**独立聚合**得出，再让勾稽关系做**校验**（而非做**计算**）。
3. **口径变更必须全量重算**。如果中途改了清洗口径，必须从头重跑，不许只重算受影响的那几个月——那正是「8/9月对、7月错」这种半对形态的成因。

## 3. 数据处理一致性三铁律

**真实事故（R20）**：餐饮账本任务中，金额有两种形态——数值型 `-570`、字符串型 `'1,122元'`。清洗用 `re.sub(r'[^0-9.\-]','',amt)` 把字符串转成**正数**，而求和条件写的是 `金额 < 0`，结果这两笔成本（合计 **1694 元**）被**静默丢弃**：7 月利润从 12923 虚高到 14617（+13%），而交付文档还写着「4 个带元的金额都已正确转换」——**零提示**。收入侧恰好走「类型==收入」判断，反而全对，形成「同一批脏数据、一半对一半错」的隐蔽形态。

1. **符号按业务语义决定，不依赖原始符号**。成本 = `abs(值)` 后置负；收入 = 正。不要用 `值 < 0` 判断"这是成本"——脏数据里符号会丢、会写在括号里 `(1122)`、会写成 `1122元`（无符号）。**类别由「类型」字段决定，不由符号决定。**
2. **清洗前后必须做一致性断言**。清洗脚本运行完，必须输出并核对：
   - 记录数：`原始行数 - 显式跳过行数 == 清洗后行数`
   - 分类笔数：收入笔数、成本笔数前后一致
   - 金额总和：**差异必须能被逐项解释**（哪一行、为什么、差多少）
   任何无法解释的差额 = bug，不是"脏数据本来就乱"。
3. **自己打印过的异常清单，必须逐项核对处理结果**。如果你已经 print 出「4 个非数值金额」，那么清洗后必须回读一遍，确认 **4 项都被正确纳入计算**，而不是"我看到了、我改了"就算完。

## 4. 交付前自读回验

**核心区别**：`我改了 X` 是**自述**；`我读回产物、X 的结果是 Y` 才是**证据**。

交付任一产物前，必须**真实读回自己产出的文件**并与源数据对账：
- **xlsx / csv** → 用代码回读，打印关键单元格，与源值比对
- **PDF** → `pdftotext` 抽文本层（抽不出中文 = 无文本层，立即修）
- **HTML / 图表** → 浏览器或渲染工具实际打开，读回渲染结果
- **数值类结论** → 用独立路径（不同库/不同公式）复算一次，与主路径比对

**回验发现的任何不一致，必须在交付物里显式写出**（「已复核：A 与 B 差 N，原因是 C」），而不是悄悄改掉或忽略。若无法解释差异，如实标注「该数字未通过复核，可信度存疑」。

## 5. 数据任务强制可视化（V1）

任何涉及 ≥3 个数值的比较 / 趋势 / 占比任务，除表格外**必须产出至少一张图**（PNG 或交互式 HTML）。

图表必须有：标题、轴标签或图例、**数据来源与抓取时间**。

中文字体用 WenQuanYi：`/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc`（`TTFont(name, path, subfontIndex=0)`）。
**不要用 Noto CJK** —— 它是 CFF/OTF 轮廓，reportlab 会报 `postscript outlines are not supported`。

图做完用 `view_image` 自己看一眼，确认中文没变成豆腐块、没有重叠、没有裁切。看不了就说看不了，不许默认它是好的。
